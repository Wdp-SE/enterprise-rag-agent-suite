# 检索与审查质量迭代 V2 设计

## 目标

提升检索证据覆盖率，让假设性变更审查更容易核验；同时保留当前 V1.0 行为、冻结评测记录和人工最终审核机制。

## 当前基线

- 当前公共语料包含 52 份 Apache DolphinScheduler 官方来源，覆盖 3.4.2 和 3.4.3。每份已收录资料都记录来源 URL、仓库提交、路径、语言、许可证和 SHA-256。该快照只覆盖部分主题，不是上游完整文档集。
- 当前检索策略为 BM25、已选定的 Chunk A 和 Top-5。冻结评测包含 46 个查询和锁定的 DEV/HOLDOUT 切分；跨文档双来源完整命中为 0/4。
- 公共 Agent 已支持自然语言描述变更、检索当前版本证据、可选的带引用模型建议和会话内人工审核。它不会写入公共基线或上游仓库。
- 当前限制包括主题覆盖较窄、多来源证据召回较弱，以及自由文本审查建议没有稳定地拆分假设、证据缺口和审核动作。

## 设计决策

### 保留 V1.0 记录

将现有 52 份来源、评测查询、Ground Truth、选型锁和 final selection 结果作为 V1.0 基线。不得改写这些历史结果，也不得用其 HOLDOUT 查询调参。

新增独立版本的质量迭代数据集与切分。新问题从官方来源和有记录的真实版本变更中整理，也可加入明确标注的假设案例。每条问题记录版本范围、预期来源 ID、是否可回答，以及是否需要多个独立来源共同支持。来源 ID 使用版本、语言和文档键组成的稳定标识，不依赖 manifest 行号。新 HOLDOUT 锁定后，只在 DEV 调整完成时用于最终验证。

### 扩充相关官方来源

在工作台已覆盖的领域中补充完整、版本配对的官方文档，例如参数行为、工作流/任务行为、API、配置和升级变更。只有审查场景确实需要时，才加入官方 Release Notes 及直接相关的提案、Issue 或 PR。

每个新增来源都必须记录固定的上游提交或 Release、规范 URL、仓库路径、语言、许可证/归属信息、抓取时间和 SHA-256。不得把合成文本伪装成上游资料，也不得无差别索引整个源代码仓库。假设变更只出现在评测输入中，并明确标注为假设。

### 用评测决定是否修改检索

保留现有 BM25 排名作为对照基线。新增离线对比，仅测试范围明确的改进，例如使用现有来源元数据加强文档标题和继承章节路径。分块或排序有任何变化，都要先在新的 DEV 集上评测；候选确定后，才在锁定的新 HOLDOUT 上作最终对照。

至少报告按去重来源计算的 Recall@5、MRR、nDCG、多来源证据完整召回、无答案问题的行为、引用来源有效性和本地 warm P95 延迟。检索结果与答案生成质量分开报告。只有证据召回提升可复现，且 HOLDOUT 与延迟没有明显退化时，才升级默认策略；否则保留 BM25 并记录失败分析。

### 结构化审查建议协议

保留自然语言请求入口和人工审核边界。让模型返回紧凑、结构化的审查结果，字段包括：

- 变更假设和范围；
- 建议核对的段落或文档，并明确标为候选；
- 证据 ID，以及每个来源与变更相关的原因；
- 证据缺口、来源冲突或版本歧义；
- 建议审核人员执行的动作；
- 明确的“等待人工审核”状态。

已确认的文档关联仍由确定性逻辑产生；只有登记过的显式来源关系才可标记为已确认，模型不能创建或升级为已确认。服务端必须校验模型返回的每个证据 ID 是否属于本次请求提供的证据。引用了集合外资料、返回格式错误、模型不可用或证据不足时，不得展示为有效建议；系统应弃答或回退到可见的检索证据。模型建议不得修改官方资料、创建上游变更或自行批准。

### 保留公开工作流边界

本轮审查草案和决定仍只保存在当前会话中。界面可以展示结构化字段和证据缺口，但本设计不增加持久化账户、审批数据库、外部工单集成、自动应用补丁或新的公共基线。

## 数据流

1. 用户提交自然语言假设变更及当前固定版本范围。
2. Agent 通过公共 RAG API 检索当前版本候选资料。
3. 若配置了模型服务，审查接口只将这些候选证据片段交给模型，要求返回结构化审查结果。
4. 服务端校验响应格式与证据引用。
5. 工作台分别展示候选资料、已确认关系、建议影响、证据缺口和审核动作。
6. 人工在当前会话中记录“已审核”或“退回”；不改写公共来源。

## GitHub 与发布规则

- `main` 是唯一的公开主线，代表最新公开版本。
- 本轮在 `codex/retrieval-review-quality` 或带日期的同类分支上实施；分支从最新确认的 `origin/main` 创建，不直接在 `main` 开发。
- V1.0 基线与 V2 评测新增内容放在可整体审阅的一组变更中。只暂存明确列出的文件，不使用 `git add .`。
- 提议合并前，确认 tracked 工作区干净，检查暂存文件清单和完整 diff，运行 `git diff --cached --check`、定向测试、语料/哈希校验和新的 DEV/HOLDOUT 评测门槛。不得提交密钥或本机私人路径。
- Push 与合并是发布动作。本任务授权在完整 diff 审阅且全部检查通过后，快进更新 `main` 并普通 push；禁止 force push。若 `origin/main` 前进或分叉，停止并先协调，不覆盖远端工作。更新后确认 GitHub `main` 指向预期提交。Render 和 Streamlit 应绑定 `main`，再核验平台部署提交，避免把功能分支误认为公网最新版。

## 验证标准

- 新增官方来源与固定 SHA-256 和 manifest 元数据一致；生成 chunk 保留来源、版本和章节路径。
- 现有 V1.0 语料与冻结评测仍可识别，不会被悄悄当作 V2 Ground Truth。
- 新评测切分可确定性重建、哈希锁定，DEV 与 HOLDOUT 分离。
- 检索对照按类别和整体报告指标，包括多来源问题与无答案问题。
- 审查 API 测试覆盖有效引用、引用集合外的 ID、证据不足、冲突/版本歧义、模型格式错误和服务不可用回退。
- Agent/UI 测试验证已确认文档关联与建议段落影响的区分、证据缺口展示、人工审核保留和公共基线不变。
- 运行定向服务、Agent、UI 测试和 `git diff --check`；不跑无关检索实验，不改 V1.0 final selection 结果。

## 不在本轮范围内

- 在新评测支持之前替换 BM25。
- 未经单独决定就修改 3.4.2/3.4.3 版本范围。
- 自动写入文档/代码、创建上游 PR、部署、持久化审批或改变 Agent 权限。
- 大范围 UI 重设计或无关清理。
