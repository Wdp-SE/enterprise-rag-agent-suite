# 面向工业边缘 AI 设备研发的单一语料迁移设计

## 1. 目标与已确认范围

本项目继续作为一个项目：**面向工业边缘 AI 设备研发与交付的版本化知识 RAG 与变更影响审查 Agent 原型**。它服务于研发、测试、交付工程师的资料查询，以及工程变更后的影响候选整理。RAG 按明确的产品/硬件型号、软件栈和资料快照检索可追溯证据；Agent 基于证据整理可能受影响的兼容性说明、配置、部署和测试资料；工程师负责判断和确认。系统不自动更改上游资料，也不声称自己是企业生产系统。

本次确认将活动演示语料统一为 **Seeed reComputer Industrial / Jetson 边缘 AI 设备中文公开资料**。Autoware、Apache DolphinScheduler 和合成企业业务资料退出在线检索、默认工作台和公网部署包。通用 RAG/Agent 能力保留。历史评测报告可作为注明旧语料、旧代码和不可代表当前效果的档案保留；测试所需的极小合成 fixture 只能留在测试目录，禁止进入活动索引或发布制品。

项目用于秋招展示 AI 应用工程能力，不冒充 Seeed、NVIDIA 或其他公司的内部系统，不宣称这些公开文档证明了真实企业的 CR/ECO 流程，也不把用户编写的演示变更描述包装成真实工单。

## 2. 方案比较与选择

1. **推荐：单一产品域迁移。** 以 reComputer Industrial / Jetson 公开中文工程资料作为唯一活动语料，保持通用检索、证据和审核能力，重建该领域的检索评测与 Agent 规则。优点是演示对象具体、业务闭环一致；代价是需重新采集和审核来源，旧 Autoware 指标全部失效。
2. **只删旧语料，保留空工作台。** 改动最少，但无法展示真实查询与变更审查闭环，也无法测量效果，不满足求职项目目标。
3. **新旧语料并列为多个工作区。** 可以复用旧资产，但会继续产生用户已指出的领域混杂和“系统到底服务谁”的问题，增加配置、测试和部署面。

采用方案 1。活动语料只设一个领域，不设置 Autoware/DolphinScheduler 切换入口，也不为保留旧评测而保留旧语料运行分支。

## 3. 语料边界、版本语义与来源治理

### 3.1 纳入范围

建立来源 allowlist，优先收录能直接支持工程查询和变更核查的中文公开资料：

- Seeed reComputer Industrial 的产品/型号指南、规格和公开安装/部署说明；
- 设备支持矩阵、Jetson 模组 SKU 与 L4T/JetPack/BSP 对应资料；
- 公开硬件接口、载板或电源/热设计资料，仅在具体文档或文件的许可允许复制、解析和再发布时收录；
- 有明确许可的固件、驱动、Yocto 构建/刷写说明及公开验证步骤；
- 有明确来源与许可的中文测试、故障排查和交付资料。

候选来源包括 Seeed 中文官方 Wiki 页面、其明确开放许可的官方硬件资料仓库，以及各自引用的公开文件。来源目录与文件格式的多样性是目标，但许可审查优先：仓库代码许可证不能自动推定 Wiki 页面、图片、PDF、原理图或二进制文件都可再分发。每个纳入文件都必须逐项记录许可与归属；许可不清楚的只保留链接、标题和必要的来源元数据，不复制正文或图片进入公开索引。

初始来源盘点从这些一手来源开始，不预先承诺其中每个文件都会被复制到语料：Seeed Jetson 设备支持矩阵（<https://wiki.seeedstudio.com/cn/jetson_developtool_supported_devices/>）；Seeed Jetson 载板 Yocto 构建与刷写指南（<https://wiki.seeedstudio.com/cn/build_and_flash_yocto_for_seeed_jetson_carrier_boards/>）；reComputer Rugged J40 入门资料（<https://wiki.seeedstudio.com/cn/ai_robotics_recomputer_rugged_j40_getting_started/>）；Seeed Jetson 系列开放硬件仓库（<https://github.com/Seeed-Studio/OSHW-Jetson-Series>）。具体设备型号、历史版本覆盖与可再分发许可须在盘点时从页面和各文件本身核验，并固定来源修订；代码仓库的许可证不代替硬件图纸或文档文件的许可审核。

采集前先生成来源盘点表，字段至少包括：来源 URL/仓库、固定 commit 或页面版本/抓取日期、标题与路径、语言、文件格式、单项许可/署名要求、产品族/精确型号、模组 SKU、软件栈版本、章节/页码、内容 SHA-256、解析状态和纳入理由。来源不足以支撑重要评测类别时，先调整可纳入来源范围并说明缺口，不用生成内容填充成“真实资料”。

### 3.2 不混淆三种版本

- **资料快照**：语料在某个仓库 commit 或网页抓取日期的冻结内容，用来复现检索索引；它不是产品发行版。
- **设备配置**：产品族、准确设备型号/载板、Jetson 模组 SKU，以及用户明确选定的 JetPack/L4T/BSP 组合。各项只允许使用源资料能证明的组合。
- **`latest`**：当前资料快照中，经清单校验且按来源声明确认的最新受支持组合；只在指定产品型号/软件基线上解释，不代表整个 Jetson 产品线或一个复合的“最新版本”。若资料没有明确时间/产品版本关系，展示“资料快照日期”或“来源未声明”，不推断版本。

界面和 API 必须分别展示资料快照与设备/软件配置；检索缺少必要型号或基线且会改变结论时，提示用户补充或并列返回适用范围，不悄悄把不同 SKU、载板或 L4T 资料混合成一个结论。

### 3.3 不纳入范围

- Autoware、DolphinScheduler 以及其他不属于 reComputer Industrial / Jetson 设备研发与交付的活动语料和问答示例；
- 无许可依据的企业内部资料、工单、BOM、测试记录或从真实企业数据推测的内容；
- 未标注来源的人工合成资料、虚构兼容关系或未经复核的 OCR 结果；
- 对完整 Seeed/NVIDIA 产品线或其企业研发流程的覆盖承诺。

## 4. 检索与变更影响审查

### 4.1 RAG 查询

用户可以直接查询中文研发资料。查询上下文包含选择的产品型号/设备配置（已知时）、软件栈基线、资料快照和资料类型。返回内容保持原文证据、标题、章节/页码、固定来源地址、源版本、语言、文件类型与许可归属可追溯。候选排序分数只作为相关性排序线索，不显示为事实正确概率。

首个活动检索策略由新语料的冻结评测选择。BM25 作为可解释基线保留；分面召回、稠密/混合检索、OCR 和 rerank 只作为候选。图片或图纸内容只有在图片来源许可清楚、抽取/OCR 结果经过人工抽样复核并能回链到原页时才进入检索；未验证的图像文字不能作为肯定结论证据。检索多召回、再排序或阈值的改动必须由该语料上的留出集支持，不能因为离线题目通过就自动上线。

### 4.2 Agent 变更审查

演示输入是一段明确标为“示例/假设”的设备或软件基线变更描述。Agent 采用领域类别组织查询，而不是把通用 Agent 逻辑改成产品知识硬编码。首批类别：

- 设备型号、Jetson 模组或载板替换；
- JetPack/L4T/BSP、操作系统或驱动升级；
- 接口、电源、热设计或外设配置变化；
- AI 运行时、容器/部署方式变化；
- 安装、构建、刷写或版本支持关系变化；
- 验证步骤、兼容性检查和回归测试变化。

Agent 先保留用户原始变更和目标配置，再用有限且可审计的检索计划查找显式兼容矩阵、相关手册/配置/验证资料。只有来源明确表达的关系才标成“资料已明确说明”；纯语义召回是“待人工核查候选”。如果来源不足、型号/软件基线不明、版本冲突或文档没有覆盖问题，结构化列出缺口并降低结论范围，不补写事实。输出包含变更摘要、目标基线、受影响候选、支持证据、证据缺口、建议验证项、需人工确认事项和审核结果；不生成自动执行命令或上游写回操作。

### 4.3 领域规则与通用能力边界

保留通用：版本化过滤接口、来源清单与完整性校验、检索候选/重排接口、引用校验、证据约束生成、Agent 查询预算、缺口表达、审核记录/人工确认、运行诊断、性能与评测框架。

替换为设备域配置：工作区名称、来源仓库、语言、示例问题、设备型号/软件基线筛选器、来源/兼容关系、变更类别、检索别名、无答案提示、当前策略评测绑定和用户帮助内容。领域信息以语料 manifest 与领域 profile 驱动；避免把 Seeed 型号和词汇散落写死在公共 API 核心代码中。

## 5. 评测与策略选择

当前 Autoware/DolphinScheduler 指标不得挪用到新语料。建立新版本评测，锁定语料、解析器/分块、索引、策略、问题、必要证据、设备配置和分组哈希后再比较候选。按文档/设备族分组切分 DEV 与 HOLDOUT，避免同一页面的近重复问题跨集合；上线策略冻结前不查看 HOLDOUT 逐题结果来调规则。

评测至少包含：

- 事实型中文查询、特定型号/软件栈查询、多来源关联、表格/图纸线索（来源允许时）和领域内无答案查询；
- 必需来源 Recall@K、完整证据集命中率、MRR/nDCG、型号与 L4T/JetPack 正确率、错误基线召回率、无答案拒答/误答率、引用证据一致性；
- Agent 变更类型与查询计划覆盖、显式关系命中、候选影响 precision/recall、无支持结论率、必需人工核对项遗漏率；
- 检索与端到端延迟 P50/P95、生成调用/失败状态，作为准确性与工程体验的联合取舍依据。

检索指标不等同答案正确率，Agent 流程覆盖不等同真实影响分析正确率。人工评审采用预先定义的 rubric，记录逐题失败原因；对真实用户流量没有数据时明确标为离线原型评测。最终公布的默认策略、Top-K 和可选阈值必须绑定构建、语料、题集与配置指纹；未通过预先锁定的门槛则保留 BM25 基线或拒绝发布策略声称，不挑最好看的单一指标。

## 6. 工作台、部署与退役

工作台、API `/public/workspace`、健康状态、README、来源页、示例问题、Render 构建配置和发布 smoke test 统一只描述这个活动设备域。默认范围应是已验证且来源最新的设备配置；筛选项必须来自 manifest，不展示旧 Autoware 的语言/版本选项，也不提供旧语料切换入口。

公网 RAG 部署显式加载新语料根目录和匹配的 retrieval config；构建身份要包括领域 profile、corpus manifest、chunks/索引和评测指纹。启动/发布校验遇到 Autoware 或 DolphinScheduler manifest、遗漏许可字段、哈希不匹配或错配策略时应失败关闭，不能静默回退到旧 `public_corpus`。

迁移分两阶段：先在独立目录构建并验证新语料、策略与工作台；达到验收条件后再删除旧语料的数据索引和旧领域采集脚本/配置，移除旧领域入口与运行时引用。旧评测报告若保留，只放在显式标为“历史档案/不代表当前系统”的目录，不纳入公网包、默认 README 主流程或当前 `/public/workspace` 指标接口。测试用最小 fixture 不得包含真实旧语料的可检索正文。

## 7. 验收条件

1. 发布制品实际只含经许可审查通过的新领域中文来源；每一条索引证据可通过清单追溯至来源、版本/快照、SHA-256 与许可/署名。
2. 版本字段区分资料快照、设备型号和软件基线；测试证明过滤不会把不同 SKU、载板或软件版本证据伪装成同一配置结论。
3. API、工作台、检索提示、Agent、来源页、README、健康状态及部署配置不再将 Autoware/DolphinScheduler 作为活动业务；对错配语料的测试失败关闭。
4. 新的冻结 DEV/HOLDOUT 评测可重复运行；发布报告明确语料和代码指纹、分母、指标定义、失败案例和局限，并且不把检索命中率说成答案准确率。
5. 至少覆盖资料查询、设备/软件基线过滤、一个跨资料变更审查、一个资料不足的拒答/缺口案例和人工审核闭环；关键变更结论都能回到证据或明确显示缺口。
6. 相关单元、API、UI、发布 smoke/integrity 测试通过；公网部署检查确认实际加载的是新构建身份和语料。公网发布应在实现通过检查后执行，不将本地 UI 可打开误报为公网已更新。

## 8. 非目标

- 建成 Seeed/NVIDIA 官方或企业内部文档系统，覆盖完整产品线或真实企业变更审批；
- 构建真实 CR/Jira/PLM、BOM、ERP、CI/CD、设备实验室或企业身份权限集成；
- 让 Agent 自动判定硬件兼容、安全合规，或自动烧录/部署/修改上游资料；
- 为填充语料而伪造公司内部资料、未验证的硬件关系或生成式测试成绩；
- 在无重新评测的前提下声称新领域策略已经比旧策略更准确。

## 9. 实施前置条件与当前状态

这份设计批准后，下一阶段再制定文件级实施计划。实施首先完成逐源许可/署名核验与新语料可用性盘点；只有合规来源和多类实际文档足以覆盖验收用例，才生成可公开索引。若盘点发现关键资料不能合法复用或版本证据不足，应报告缺口并调整数据范围，而不是用未经授权的内容或合成数据填补。

当前工作区存在既有的未提交设计改动和未跟踪资料目录，本次设计文件需单独处理；后续实施不得覆盖或纳入这些无关改动。
