# RAG 检索与变更审查 Agent 准确性改进设计

- 日期：2026-10-01
- 状态：待用户审阅
- 设计基线：`origin/main`，提交 `446b5be`
- 范围：Autoware 公开语料演示中的 RAG 检索/生成，以及证据约束的变更影响审查 Agent
- 本文性质：设计规格，不代表本文中的候选策略已经实现或达到目标指标

## 1. 背景与问题

系统面向研发工程师、变更审查人和技术负责人。研发工程师需要按明确的产品/资料版本查到可核验依据；审查人需要发现变更可能影响的设计、配置、接口和测试材料，并能回到原始来源复核。两类任务的错误代价不同：普通知识查询偏重答案有据、版本正确和快速响应；变更审查偏重关键影响不漏检、来源可追溯，允许多给出标注清楚的候选并交由人工判断。

当前 RAG 的主要问题已由仓库内冻结评测暴露：精确检索整体较快、版本误召回为零，但跨资料完整命中、跨语言证据和图片证据仍有缺口。Agent 的查询规划单测覆盖了分类和预算等局部行为，却没有覆盖“规划查询 → 多语言检索 → 证据汇总 → 影响候选”的端到端效果。当前结果不能据此宣称线上答案准确率或幻觉率。

## 2. 现有证据与边界

基于当前 `origin/main` 的 Autoware 冻结评测：82 个问题，DEV 51、HOLDOUT 31。所选运行策略为 `bm25_figure_ocr`。HOLDOUT 上，BM25 的 required-source recall@5 为 91.43%，完整来源命中率为 89.29%，MRR@5 为 73.19%，图片证据命中 0/3，错误版本数为 0，P95 检索耗时约 46.58 ms。BM25 加已复核 OCR 后文本指标基本不变，图片证据为 2/3，错误版本数为 0，P95 约 47.19 ms。

现有名为 Hybrid 的方案使用字符哈希稠密表示，并非神经语义向量。其 HOLDOUT required-source recall@5 为 82.86%、完整来源命中率为 78.57%、MRR@5 为 50.16%、图片证据命中 0/3、错误版本数为 0、P95 约 49.75 ms，低于 BM25。Facet RRF 也未提升文本指标。BM25 与 BM25+OCR 的 Top-5/Top-20 探查未发现新增必需来源，表明单纯增大候选数或调整排序不足以修复候选池缺少相关资料的问题。

对 6 个无答案探针，检索均返回候选；这只说明需要评估拒答和证据充分性，不能当作幻觉率。DEV 上临时加入术语表的探索性实验有改善，但术语表是在观察失败类别后临时构造，且未在独立集上验证，存在过拟合风险，不作为发布依据。当前跨语言遗漏和中英关系标记也不充分，不能把路径相似、标题相似或社区翻译直接说成已验证的一一对应关系。

Agent 现有路径最多规划 4 个查询，每个查询调用 RAG 时使用 `language="zh_preferred"`、`top_k=5`，送入模型的证据最多 5 个片段。因此英文官方资料可能在显式双语审查时漏掉。现有 28 条 Agent planning V1 评测不调用 RAG 或生成；其 HOLDOUT 在规则定型过程中已被检查，不是独立、无偏的最终评测集。

以上数值均是固定语料与当前运行环境下的离线检索结果，不等同于答案正确率、企业线上 SLA 或真实用户体验。更换数据、模型、依赖、运行资源后必须重新测量并标记对应指纹。

## 3. 目标与非目标

### 目标

1. 在版本/来源/权限等硬边界不被检索策略放宽的前提下，提高双语问题对相关证据的召回和跨资料完整性。
2. 让回答与审查结论只引用检索到且经过规则校验的证据；证据不足时明确展示缺口或拒答，不用语言流畅度替代证据。
3. 使 Agent 的影响候选覆盖、漏检风险、证据链和人工审核结果可评测、可复核。
4. 在检索质量、端到端延迟、调用量、失败率和运行资源之间做有数据支撑的取舍。
5. 建立独立、冻结、分层的评测集，避免在同一 HOLDOUT 上反复调参后仍把它称为独立验证。

### 非目标

- 不承诺 100% 准确，也不把离线检索指标表述为线上答案准确率或幻觉率。
- 不自动修改或写回上游文档、代码、工单或公共知识库；最终决定仍由人工审核。
- 不因单次 DEV 探索结果直接替换 BM25 默认策略。
- 不把未验证的中英文资料关系包装为已对齐，也不把区域差异误报为翻译遗漏。
- 当前阶段不引入 GraphRAG 全局摘要链路；核心任务是特定变更下的证据检索和候选影响发现。
- 不把模型自报的概率分数直接显示成“置信度”。

## 4. 用户需求与指标取舍

| 用户 | 主要任务 | 更重要的质量属性 | 可接受的取舍 |
|---|---|---|---|
| 研发工程师 | 查询特定版本的设计、配置、接口或运行资料 | 版本正确、引用可回查、回答有依据 | 对一般问题优先低延迟；证据不全时接受部分回答或拒答 |
| 变更审查人 | 判断变更可能影响哪些资料、功能和验证项 | 关键来源召回、影响覆盖、缺口清楚、可审计 | 可接受比普通问答更高的延迟和候选数量，但候选必须标明依据与不确定性 |
| 技术负责人/质量人员 | 复核风险、确认或退回审查建议 | 严重影响项少漏检、结论与来源可追溯 | 不能由模型替代签字或审批；不确定项进入人工核验清单 |

本设计不预先编造延迟 SLA、准确率承诺或成本上限。实施计划中应根据本地与公网运行资源，和可重复评测结果一起提出目标值，先冻结再测。

## 5. 建议方案

### 5.1 RAG 检索链路

**硬过滤先于排序。** 查询候选必须先满足选定知识空间、资料版本/范围、授权状态和来源策略。版本过滤失败不能靠语义分数补偿；存在多个版本时，结果须显示实际命中的版本。语言策略决定候选语言，不得暗中把“中文优先”解释成“只搜中文”。

**保留 BM25 精确基线，新增真正的多语言语义候选作为可对照实验。** 可评估 BGE-M3 一类多语言稠密/稀疏检索候选，并与经人工审核的技术术语、缩写和中英别名结合。字符哈希 Hybrid 只作为已测过的旧基线，不能称为神经语义检索。对各路候选使用 RRF 等简单融合方法可以作为实验组，但融合方法没有天然收益保证，必须在未参与调参的集上验证。

术语词表及中英关系都需要来源、版本、审核状态和更新时间。未经核验的社区翻译只作为独立来源的可检索资料；语义相似或路径映射不得自动生成“官方对应”关系。检索结果应区分官方原文、社区翻译、审核通过的术语映射和待核验候选。

**重排放在候选召回之后试验。** 当候选生成确实带回必需来源后，才比较跨语言 reranker（例如 BAAI bge-reranker-v2-m3）对排序和端到端质量的增益。需同时评估模型大小、冷启动、内存、推理耗时和公网可运行性。重排无法找回从未进入候选池的文档。

**图像/OCR作为独立证据通道。** 保留文档、页码/图号、提取方法、OCR文本和复核状态之间的关联。先处理图片类评测题的证据召回，再按错误案例比较 OCR、表格/图注结构恢复及必要时的视觉模型方案。模型提取文本标注为派生证据，不冒充原始文字；用户始终能打开原图或固定来源。

### 5.2 生成与证据充分性

回答阶段应执行服务端证据门槛：每个事实性结论只允许引用本次检索返回的 evidence ID；证据版本和来源必须满足本次查询范围；引用 ID 必须真实存在；关键主张需要能够映射到支持片段。没有充分证据时，生成部分答案并列出未覆盖点，或明确拒答，不能用提示词要求代替后端校验。

不展示未经校准的数值置信度。首阶段展示可解释的证据状态，例如“有直接证据 / 仅有间接证据 / 证据不足”，附带覆盖的必需问题点、来源数量及版本检查结果。若未来要引入概率分数，必须用独立人工标注集校准，并报告校准误差和不同业务类别下的风险。

### 5.3 变更审查 Agent

将变更输入拆成结构化字段，如目标组件、版本、变更类型、变更说明和显式受影响对象；模型可以协助抽取，但字段缺失和解析不确定性要显式呈现。针对参数、接口、功能新增/删除等变更类型维护可审计的检索检查项，作为规划器约束与补充，而不是让 LLM 自由生成后直接执行。

每个检查项同时构造原文术语、规范化对象名和经审核的中英别名查询。双语审查必须查询两种语料并把语言分别呈现；普通单语问答遵循用户选择，不无故增加成本。后端为每项检查保留查询数、总候选数、超时和停止原因等硬预算及轨迹。

先依据显式、已审核的组件关系、版本关系和文档链接找已知关联；这些关系要携带来源及生效版本。RAG 用来补充发现潜在相关资料。输出分成“已验证关联”“影响候选”“语言/版本对应关系待核验”“证据缺口/建议检查项”。候选不能伪装为确定影响；证据不足或关键检查项未覆盖时，不能输出“无影响”式完成结论。由人工确认、驳回或补充，并保留审核记录；不写回上游系统。

### 5.4 端到端可观测性

一次审查至少应能关联：变更输入摘要、规范化字段、规划的检查项、每次检索查询、过滤条件、证据 ID 与来源指纹、生成主张及引用、质量门禁结果、模型/提示词/语料/索引指纹、耗时和调用错误、人工审核结果。公网上线时遵循最小化日志原则，不记录不必要的敏感文本；当前公开演示语料不可用于推断企业私有数据治理已完成。

## 6. 评测规格

### 6.1 数据集

为避免复用已被查看和调参的 V1 HOLDOUT，建立新版本的冻结评测：

- RAG 数据覆盖中问英答、英问中答、同语言问答；精确术语、同义改写、跨文档组合、版本易混、图表/截图、证据不足/不可回答问题。
- Agent 数据覆盖主要变更类型、单文档与跨文档影响、显式已知关系与未知关系、双语资料、版本冲突、误报和关键影响漏检案例。
- 每题标注必需来源、支持答案点/主张、版本范围、语言、关系状态、图片证据位置、是否应拒答及可接受的影响候选。Agent 案例另标影响严重度和必须覆盖的检查项。
- 按文档族、主题和版本分组切分 DEV/HOLDOUT，避免同一文档的近似页面同时泄漏到两侧。标注说明、标注人复核、语料 hash、数据版本、模型及配置都随结果记录。
- 具体样本数量和置信区间要求在实施计划阶段结合人工标注能力与误差容忍度确定；不能为了漂亮百分比而挑题。

### 6.2 指标

| 阶段 | 必须报告的指标 |
|---|---|
| 检索 | required-source recall@5/@20、完整来源命中率、MRR/nDCG、版本错误数、来源权威性命中、语言方向覆盖、图片证据召回 |
| 回答 | 必需答案点覆盖、可验证主张支持率、引用精确率/召回率、无依据主张比例、拒答精确率/召回率、按证据覆盖率绘制风险-覆盖曲线 |
| Agent 审查 | 关键影响来源召回、影响候选精确率/召回率、严重度分层漏检率、检查项覆盖率、错误“无影响”结论数、关系状态分类准确率、人工复核负担 |
| 工程运行 | 端到端 P50/P95、检索/模型各阶段耗时、LLM 调用次数与 token/费用、超时/错误率、峰值内存、冷启动时间 |

所有指标按普通问答/双语审查/图片类/无答案、语言方向、版本及风险等级分层；只给总体平均会掩盖关键失败类别。离线数据集的答案支持指标不叫“线上准确率”或“幻觉率”。

### 6.3 晋级门槛

在跑新 HOLDOUT 前冻结目标指标和预算。候选策略需要满足：版本错误为零；关键审查项的召回不得低于预设安全底线；目标场景的完整证据/答案支持指标相对基线有可重复改善；延迟、调用费用和内存不越过预先批准的预算；拒答行为在无答案集上符合预期。若没有满足门槛，保留当前 BM25+OCR 基线并记录失败原因，不因单一指标提升晋级。

具体阈值、显著性/区间报告方式、运行环境、API 模型及部署预算由实施计划明确后再执行，不能事后按结果改变规则。

## 7. 分阶段落地建议

1. **先修评测可信度：** 审计现有 V1 数据和标注，整理失败分类；建立不被调参使用的新双语 RAG 与端到端 Agent 评测集和指纹机制。
2. **再改善候选证据：** 保持 BM25+已复核 OCR 基线，离线比较多语言稠密/稀疏、审核术语表、语料关系提示和融合策略；检查各语言方向及图片子集。
3. **再优化排序和回答：** 仅在候选召回提升后比较多语言重排；引入结构化证据门禁、主张引用校验、缺口和拒答评估。
4. **再改 Agent 审查闭环：** 结构化变更、双语按项检索、已审核关系优先、候选与缺口分层输出、硬预算及人工审核轨迹；跑端到端新 HOLDOUT。
5. **最后评估发布：** 在本地和公网目标资源测冷启动、P50/P95、失败率、费用及人工体验。通过事先冻结的门槛后才考虑成为默认并单独安排部署验证。

上述阶段次序是建议，不是授权本次立即下载新模型、改依赖、访问或修改线上密钥、推送 main 或发布公网。

## 8. 主要风险及控制

- **评测过拟合：** 使用全新分组 HOLDOUT；将探索集与最终报告清楚分开。
- **中英来源不等价：** 关系状态显式管理；社区译文标记来源属性；未核验关系不得用于声称同步或漂移。
- **检索增加延迟和资源：** 每个候选单独做消融，测冷启动/常驻内存/耗时/费用，并允许保留 BM25 回退。
- **图像解析错误：** OCR/视觉结果保留派生标志与原图位置，并单列图片评测，不把提取结果默认为事实。
- **Agent 漏检被误读为无风险：** 关键检查项覆盖门禁；覆盖不全时不得给出“无影响”结论。
- **可观测性泄漏：** 公网和未来企业部署按最小必要原则处理用户输入、凭据和审查日志。
- **公开原型与企业承诺混淆：** README、UI 和简历区分已实现能力、公开资料实验和生产化待办。

## 9. 参考资料

以下资料用于启发候选方法，不代表本项目已经采用或能取得同等效果：

- BEIR：跨检索任务基准研究，说明 BM25 仍是有竞争力的强基线，reranking/late interaction 可提高效果但通常有计算代价。[论文](https://arxiv.org/abs/2104.08663)
- Reciprocal Rank Fusion：融合不同检索列表的排序方法；是否提升仍需针对本项目验证。[Google Research 论文页](https://research.google/pubs/reciprocal-rank-fusion-outperforms-condorcet-and-individual-rank-learning-methods/)
- BGE-M3：多语言、多功能检索模型候选，可作为双语检索实验对象。[论文](https://arxiv.org/abs/2402.03216)
- BAAI bge-reranker-v2-m3：多语言重排模型候选；应验证模型资源及端到端成本。[模型卡](https://huggingface.co/BAAI/bge-reranker-v2-m3)
- RAGAS 指标文档：提供检索、忠实度、多模态和 Agent 指标的参考框架；本项目仍需用人工标注的研发变更任务定义业务指标。[指标文档](https://docs.ragas.io/en/latest/concepts/metrics/available_metrics/)
- GraphRAG 论文：面向语料全局问题的图索引与摘要思路；本设计当前聚焦局部、版本受限的变更证据，不把它作为默认方案。[论文](https://arxiv.org/abs/2404.16130)
