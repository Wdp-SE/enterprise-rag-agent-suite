# 版本化研发知识 RAG 多来源与图片证据优化设计

## 目标

在不破坏现有 BM25 文本检索和版本边界的前提下，改善复合问题的多来源证据召回，并让用户能够检索官方研发文档中图片独有的信息。新策略必须通过独立的、可复现的离线评测后，才可成为公网默认策略。

## 当前基线与已知约束

- 公网官方知识路径使用固定 Apache DolphinScheduler 3.4.2/3.4.3 资料，共 132 份 Markdown 来源和 1322 个文本片段；当前索引不含图片 OCR 内容。
- 正式检索基线为当前 heading/paragraph chunks、BM25、版本范围先过滤、Top-5。零分结果会被剔除，但正分候选没有经校准的相关性阈值。
- 冻结 V3 HOLDOUT 不得用于调参或覆盖。其跨文档类别只有 4 题，完整来源命中为 2/4；该数字是优化动机，不是稳定的用户准确率估计。
- 旧版 52 来源实验中，固定 1250 字符 chunk 优于被测的 650 字符和带重叠章节候选；更简单的文档多样性限制没有稳定补回双来源证据。因此不能直接全库重切或全局限制每文档结果数。
- 132 个来源含 608 处相对图片引用、归并为 307 张固定版本图片；当前只校验 6 张，其中 5 张 OCR 输出仍是未审核候选。alt text 与文件名不能当作图像识别结果。
- 版本过滤、来源 ID、固定提交 URL 和现有精确文字差异提示必须继续保留。公开资料“当前版本”仍是语料清单中最新已收录版本，不承诺自动追踪上游发布。

## 设计决策

### 1. 新建 V4 评测，不改动 V3

为当前固定语料建立独立评测目录和锁定输入。评测问题覆盖：

1. 单来源精确技术问题和自然语言改写；
2. 需要两份或多份来源的跨文档问题；
3. 必须分别检索 3.4.2 与 3.4.3 的跨版本比较；
4. 图片独有文字、表格/界面截图、流程图关系及正文加图片的联合问题；
5. 语料无法回答及容易混淆的负例。

图片题从图片内容和原始上下文人工制定，并标注答案事实点、图像哈希、固定版本、所属文档/章节和预期引用。按来源文档或场景家族划分 DEV/HOLDOUT，禁止同图、同场景近似题跨组。题量不足时明确称为试验集，不发布泛化准确率声明。

冻结 V4 的问题、标注、语料清单、索引产物、策略和运行器哈希。候选策略只允许用 DEV 选择；获选策略只在 HOLDOUT 运行一次。任何策略、数据或标注变化都创建新的评测版本。

### 2. 检索候选对照

统一比较以下策略，所有策略使用同一固定来源范围、语言范围和版本过滤：

- **A：BM25 基线**，现有单查询、Top-5 行为；
- **B：分面 BM25 + 排名融合**，仅对检测为跨资料/多事实的问题生成有限的原子子问题，分别检索候选并用 RRF 合并；普通单事实问题继续使用一次 BM25；
- **C：经审核图片 OCR 侧索引**，与 A、B 分别对照，避免把“查询融合”和“补图片数据”的收益混在一起；
- **D：受控混合检索或重排**，只在 V4 DEV 显示同义改写召回不足，或正确来源已进入候选池但排名靠后时，运行可复现且资源成本可接受的候选。若模型不可稳定获取，不安装为公网强依赖，并记录未评估原因。

候选阶段使用可配置的 Top-N 评估召回（建议从 20 起），最终仍只向回答阶段提供有限证据（默认最多 5 项）。不同子问题的命中按稳定的 chunk/source/version ID 去重；追踪记录保留每个证据由哪个查询召回。只对明确需要多来源覆盖的问题做条件化融合，不做全局来源配额或固定文档上限。

### 3. 图片证据为离线、可审核的 sidecar

图片内容不在用户提问时在线下载或 OCR。基于固定 raw URL 离线取回候选图片，校验响应类型、图像签名、完整解码和内容哈希；失败资产明确记录，不猜补内容。

优先选择业务相关的界面截图、参数/状态表格和流程/架构图进行人工审核：

- OCR 文字作为独立图片证据，不混写成 Markdown 原文；记录 OCR 工具、语言、质量状态、置信信息、图片区域/页码、文档章节、版本、Git commit、raw URL 和 SHA-256。
- 未审核 OCR 不进入正式索引；审核拒绝、工具失败、低质量文字均保持不可检索状态。
- 图片区域内的关系信息若 OCR 无法表达，可试验离线图像描述，但它必须标为派生描述和探索线索，不能冒充原文或单独作为高风险结论依据。若没有可复现且可接受成本的视觉模型，则不纳入公网首版。
- UI 将图片 OCR/描述和正文片段分开显示，清晰标示模态与出处，提供固定版本图片链接/预览以供人工核验。

在现有 307 张图片中分层抽样建立试点，不把 OCR 扩展到所有图片。若只有已审查的少量图片，结果须标成有限图片子集验证，不能宣称支持所有文档图像。

### 4. 版本安全与相关性门控

- 指定单一版本时，检索前继续硬过滤；V4 显式统计版本不匹配返回数，预期为 0。
- 明确要求比较两个版本时，对两版分别检索或使用明确的双版本范围，验证两边必需证据均召回；不允许静默回退到当前版本。
- 继续把“同一章节文字不同”作为差异提示，而不宣称是事实矛盾；新的语义冲突判断不在首轮范围。
- 不用未经校准的 BM25 原始分数硬编码统一拒答阈值。若加入结果质量门控，必须用无答案/混淆题同时调节误答和错误拒答，并保留“证据不足、请人工核验”状态。

## 评测指标与晋级标准

每个候选至少报告：

- 必需来源 Recall@20、最终来源完整命中@5、证据锚点召回及 MRR/nDCG；
- 跨文档完整命中、跨版本双侧完整命中，分组报告而不只给总体平均；
- 图片证据 Recall@5、图片答案事实正确率、引用/图片定位准确率；
- 无答案误答率、可回答题错误拒答率；
- 版本泄漏计数、非目标文本题回归、warm 检索 P50/P95，以及如果使用外部模型时的推理成本。

候选只有在新 HOLDOUT 上改善预先指定的目标组指标、没有明显损害普通文本题和证据锚点召回、单版本查询无版本泄漏、无答案行为不退化，并满足部署延迟/成本约束时才晋级。以题数、置信区间或样本局限说明收益的不确定性；不把检索召回直接称为回答准确率或幻觉率。

## 非目标

- 不修改已冻结的 V3 题目、标注、策略记录或 HOLDOUT 结果。
- 不直接把生产默认检索切换为 Dense/Hybrid，不仅因“向量更语义”而引入大模型权重。
- 不全量 OCR 所有 307 张图片，不让未审核 OCR 或图像模型描述成为正式证据。
- 不新增公网请求时图片抓取/视觉模型调用；图片处理离线完成，避免线上延迟、失败和费用不可控。
- 不在这轮建设完整的图数据库、企业 ACL、文档审批平台或自动上游写回功能。
- 不改变人工最终审核边界。

## 发布与回滚

候选策略通过离线晋级门槛并完成回归后，先在功能分支合并前运行 RAG API、工作台和端到端测试。检索默认切换使用显式且可回退的策略配置；部署后检查 Render RAG API 健康状态、检索行为和 Streamlit 工作台展示。出现版本范围错误、图像引用失效、文本主指标退化或公网启动失败时，恢复上一正式策略/提交，并保留新评测结果供后续分析。
