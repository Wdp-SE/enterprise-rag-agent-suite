# Prototype Final 三分钟 Demo

## 准备

运行：

    .\start_prototype.ps1

打开 http://127.0.0.1:8502 。数据为完全合成的 demo_company_a / PAYMENT 研发资料。

## 0:00–0:25 产品问题

打开“项目概览”。

讲解：普通 RAG 在多个文档版本并存时可能混入旧答案；普通 Agent 也可能在引用过期、目标内容已变化或未经审核时写入。本系统把版本治理、引用依据和安全修改串成一个闭环。

## 0:25–0:55 版本可信检索

打开“文档与版本”，展示需求 V1 与 V2。再到“可信检索与版本差异”：

1. 默认当前有效范围查询“系统最大并发是多少”，结果为 1000。
2. 显式选择历史版本 requirements-v1，查询结果为 500。
3. 比较 V1/V2，指出 500→1000、200 MB/s 和同步→异步。

关键句：历史资料没有删除，但正式默认查询不会被历史版本污染。

## 0:55–1:35 变更影响与引用依据

打开“变更影响与修改审核”，点击“准备合成变更任务”。

1. 需求变化显示新旧内容。
2. 已确认关系来自登记的研发 Trace。
3. 疑似影响来自语义检索，只是人工审核建议。
4. 展开引用依据，查看文档名、版本、章节和页码。
5. 展示修改前与修改建议，说明只改 DES-014 指定段落。

关键句：Evidence 让结果可追溯，但不自动证明建议一定正确。

## 1:35–2:15 审核与安全写入

1. 不填写审核人时不能批准。
2. 填写审核人并点击“批准修改”。
3. 点击“应用已批准修改”。
4. 说明 Quality Gate 检查 Evidence、Scope、Freshness、基础版本、Anchor、原文哈希和幂等键。
5. 冲突分支：目标原文若在审核期间变化，状态为“目标已变化”，不会覆盖。
6. 正常路径生成候选文档。

关键句：局部 Patch 比整篇生成更容易审核、冲突检测和重复执行保护。

## 2:15–2:40 Candidate Version

点击“校验并安全发布新版本”。

展示 Candidate → Validation → Activation。强调任何校验失败都显示“当前有效版本保持不变”；成功后 design-v2 激活，design-v1 仍可历史查询，原 DOCX 不被覆盖。

## 2:40–3:00 Trace 与 Evaluation

打开“执行轨迹”：

- 展示 RAG 调用、LLM 调用、Evidence 数量和总耗时。
- 展示 Context Budget 的检索候选、校验后、去重后和最终入选数量。
- 说明页面读取真实状态，不重新执行检索。

打开“评测结果”：

- 7/7 固定用例通过。
- P50 66.852 ms，P95 77.057 ms。
- 未批准写入 0，重复写入 0。
- 离线对照中无版本约束同时召回 V1/V2，正式检索只返回当前 V2。

## 失败处理

- RAG 未启动：重新运行 start_prototype.ps1。
- 候选校验失败：保留旧有效版本，查看“技术详情”。
- 冲突：基于最新版本重新准备变更任务，不强制覆盖。
