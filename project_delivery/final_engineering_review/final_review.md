审查日期：2026-09-24。分支：`feature/public-value-prototype`。审查起点：`204a033cde7bca0f3510b4c2e69f2127e4ef3a7b`，恢复标签：`backup/pre-final-engineering-review`。本地 V1.0 候选工作区含未提交修改，尚未推送、部署或合并 main。三份原有未跟踪 DOCX 未读取、修改或加入 Git。详细审查证据与五项限量计划见 [audit.md](audit.md)。

## 1. 当前业务闭环是否成立

**成立，但仅在公开原型边界内。** 研发人员主动选择固定版本的 Apache DolphinScheduler 公开资料进行检索，查看原文与引用；也可从真实资料段落发起会话内假设变更，得到检索驱动的影响候选和草案，再由人审核。用户、触发动作、证据来源和人工决策点明确。它不是自动监听 Git/Jira/CI 的生产系统，也不代表 Apache 官方。

## 2. 是否存在根本性问题

没有发现需要推翻现有 RAG/Agent 架构的问题。本轮已知并保留的边界包括：跨文档双来源完整 Top-5 命中为 0/4；检索无答案题会返回候选，不能把候选当成答案。最终选型对照已完成，但结果仅适用于这份有限语料与小规模回顾性题集，不能外推为真实用户准确率。

## 5. 为什么值得做

这些修改分别保护**业务判断**、**评测可信度**、**证据完整性**、**公开费用边界**和**复现/面试解释**。每项都有可复现反例或实际不一致，未引入新框架、数据库或额外服务。

## 6. 明确没有做的功能

没有自动改 Apache 源码、创建 PR、发布候选版本、任意文件上传、用户系统、RBAC、多租户、MCP、Browser Agent、新向量数据库、Hybrid/Rerank 上线或核心框架重构。没有因历史文档过时而清理全仓库，也没有新增无法核验的“真实影响准确率”。

## 7. RAG 的真实边界

公开 RAG 检索 52 份选定官方资料快照的 659 个片段；版本和语言条件在排序前限制候选。当前默认 BM25。`zh_preferred` 是同分时中文优先，不是强制仅中文；“仅中文/仅英文”才是硬过滤。资料类型是显示元数据，公开 API 目前**不提供按资料类型过滤**。模型回答只在部署者配置密钥和开关后出现；引用 ID 校验保证来源属于本次检索，但不证明每句回答都获原文语义支持。无配置/弃答/失败时只显示待核对候选。

## 8. Agent 的真实边界

公开 Agent 通过 RAG HTTP 读取固定来源并调用现有 Diff/Impact API。它提出会话内假设变更与影响候选，不判断真实代码依赖。PR #18464 正文明确引用 DSIP #18454，只证明两份文档有关联；检索到的段落均需人工核对。草案和审核状态存在当前 Streamlit 会话，不写公共语料、Apache 上游或公开候选版本。人工审核没有身份认证和持久审计效力。

## 9. 版本可信边界

3.4.2/3.4.3 固定版本、语言、来源类型、原文 URL 与 SHA-256 随证据可追溯。复核结果：原始资料 **52/52** 哈希匹配；策略中的 manifest 哈希匹配；两个预生成索引资产哈希匹配。版本差异提醒只报告同文档/章节的文字差异或明确字面参数值差异，不判定哪一语言/版本“必然正确”，也不推断事实矛盾概率。

## 10. 公开资料边界

48 份官方文档的上游链接固定到 Git commit。两份 Release、一个 Issue、一个 PR 使用本地时间戳与哈希固定快照，但它们的**在线页面 URL 可变化**；关联到 3.4.3 不表示该网页正文由 3.4.3 Git commit 固定。所有资料来自公开上游，项目不是 Apache 官方产品。新克隆无需私人文档或本机旧 runtime；联网抓取不是应用启动条件。

## 11. Benchmark 能证明什么

最终选型在相同 52 来源语料、版本过滤、语言范围、Chunk A（1250 chars、无 overlap）和 Top-5 条件下比较 BM25、multilingual E5 与 Hybrid。DEV 有 22 条可回答题：BM25 Hit@1/Hit@5/MRR 为 0.3636/0.8182/0.5295；E5 为 0.2727/0.7273/0.4508；最佳 Hybrid（BM25 权重 0.75）为 0.3636/0.8182/0.5470。Hybrid 的 MRR 仅增加 0.0175，Hit@1、Hit@5 和双来源完整命中没有改善，P95 从 BM25 的 1.36 ms 增至 22.31 ms。

因此冻结正式策略为 BM25 + Top-5。锁定后 BM25 在 HOLDOUT 的 Hit@1/Hit@5/MRR 为 0.4286/0.7619/0.5833，P95 为 1.55 ms。检索质量指标仅按可回答题计算。指标、参数、耗时范围和逐题证据见[最终选型报告](../../evaluation/real_world_retrieval/final_selection/final_selection.md)。

## 12. Benchmark 不能证明什么

不能证明全站准确率、真实企业生产表现、答案事实正确或普遍优于神经语义检索。这次确实运行了真实 multilingual E5，但数据集仅 52 份官方资料和 46 条既有题目；HOLDOUT 是从先前已评测题目做的回顾性确定划分，不是独立真实用户问题集。不能把有限实验结果外推成普遍结论。

跨文档四题中，双来源完整 Top-5 命中仍为 0/4；简单增加 K 或限制同文档片段没有解决。检索本身对三条无答案题的零候选拒绝为 0/3。另一次一次性、受预算限制的生成探针观察到弃答 3/3、引用 0、观察到的错误生成 0/3；这是单次小样本结果，不是校准后的可靠性或准确率承诺。Rerank 未实现，E5 和 Hybrid 不在正式运行链路。

## 13. 真实企业环境还缺什么

正式数据授权与分类、身份/权限及租户隔离、可审计的持久审核记录、数据变更源接入、索引更新/回滚、模型调用平台级预算与滥用保护、多实例一致状态、真实用户留出集和历史变更真值评测。这些是企业部署前条件，不应因为原型本地通过测试而跳过。

## 14. 面试可以声称什么

可以说：做了固定公开资料的版本感知检索与来源溯源；在这份有限数据和既有题集的同条件小规模比较中，BM25 + Top-5 是更合适的实际取舍；multilingual E5 与 Hybrid 都做过离线对照，Hybrid 只有轻微 MRR 改善且 P95 更高；Agent 通过 HTTP 调用 RAG，区分已确认文档关联和建议段落影响；会话内假设变更由人审核，公共语料不改。必须同时说明双来源完整命中为 0/4，HOLDOUT 是回顾性划分，不是独立真实用户测试。

## 15. 面试不能声称什么

不能说：Apache 官方产品、面向生产的系统、影响已自动验证、修改会自动发布、回答绝无幻觉、引用能证明事实、无答案拒绝已达准确率、BM25 普遍优于神经检索、跨文档问题已解决、真实用户准确率很高、具备企业级多用户审批。追问“完整变更影响 Ground Truth”时应诚实回答：目前只有可核验的 DSIP↔PR 文档关联，没有足够可靠的多个 changed-files/影响真值回放样本，因此未制造 Recall@K 数字。

## 18. 是否建议补 Neural Dense Benchmark

**本轮已完成 multilingual E5 的有限同条件选型比较，不应再把该实验描述为尚未进行。** 结果没有支持将 E5 或 Hybrid 接入正式链路：E5 的 DEV 主要指标低于 BM25；最佳 Hybrid 仅小幅增加 MRR，Hit@1、Hit@5、双来源完整命中未提高而 P95 明显上升。当前冻结策略仍是 BM25 + Top-5。后续若要评估泛化，应使用独立真实用户问题集；本轮不再扩展实验，也不实现 Rerank。

## 19. 是否建议冻结功能

**建议冻结。** 当前已可作为边界清楚的公开 GitHub/秋招原型候选；再增加平台式能力会扩大不可验证范围。发布前只需人工 Code Review、确认本轮 diff 和部署配置，然后再决定提交、推送与公网验收。不要把有限原型包装为生产级研发治理系统。

## 20. 是否建议提交当前审查修改

**建议人工审查后作为一个独立修复提交**，但本轮按要求未自动 commit/push/merge/PR。提交时只按文件清单选择本轮改动与审查报告，绝不使用 `git add .`；原有三份 DOCX 继续保留在 Git 外。提交后须重新核对 Render/Streamlit 部署是否实际更新，再做公网 Smoke，不能用本地通过替代线上通过。
