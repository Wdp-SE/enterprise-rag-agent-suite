# Autoware 检索策略评测 V1

本评测针对 `versioned-rag-service/public_corpus_autoware/` 的固定语料和当前 BM25 检索实现，比较 `bm25`、`bm25_faceted_rrf`、`bm25_figure_ocr` 与 `bm25_faceted_figure_ocr`。它只评估检索候选，不调用模型，也不代表答案准确率、幻觉率、真实用户分布或公网延迟。

`cases.jsonl` 是 16 道手工题及其必需来源/图片标注；场景分组与文件哈希在 `split_lock.json`。DEV 有 11 题，HOLDOUT 有 5 题，包含当前与历史版本、单来源、多来源、两张图片独有标签和无答案问题。指标包括 Top-5 必需来源 Recall、完整来源率、图片证据命中率、错版本数、无答案题非空候选率与本机 warm 检索 P95。

## 结果与策略选择

| 切分 | 策略 | 必需来源 Recall@5 | 完整来源率@5 | 图片命中@5 | 错版本 | 无答案仍有候选 |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| DEV（11） | BM25 | 100% | 100% | 0/2 | 0 | 1/1 |
| DEV（11） | BM25 + 复核图中文字 | 100% | 100% | 2/2 | 0 | 1/1 |
| HOLDOUT（5） | BM25 | 100% | 100% | 0/2 | 0 | 1/1 |
| HOLDOUT（5） | BM25 + 复核图中文字 | 100% | 100% | 2/2 | 0 | 1/1 |

两种图片策略都通过了本题集的来源覆盖非劣化门槛并命中两张图。选择较简单的 `bm25_figure_ocr`：它不切分普通查询，在这组题中每个问题执行一次文本 BM25 和一次本地图片侧车检索；分面图片策略多做查询拆分，却未提高覆盖。策略实现要求图中文字本身至少匹配两个不同词，且图片只替换 Top-5 中重复来源的文字片段；如果没有可替换的重复来源，则不挤掉其他唯一来源。

本机 10 次重复测得图片策略 warm P95：DEV 约 2.55 ms、HOLDOUT 约 3.33 ms；BM25 约为 2.51 ms 和 3.32 ms。该差异处于本机微基准噪声范围，不代表云端端到端体验。两种策略在各自切分都只有 1 道无答案题，且均返回候选（1/1）：现有检索有噪声，暂不能宣称具备拒答能力。下一版应增加按资料类型、关键词重叠和困难负例覆盖的无答案问题，并独立评估阈值；不要在已经打开的这组 HOLDOUT 上继续调参。

## 复现

在仓库根目录运行：

```powershell
python evaluation/autoware_retrieval_v1/run_benchmark.py --repeats 10
```

评测结果写入 `results/benchmark.json`。报告记录语料、索引、图像侧车、检索代码、运行配置、题集、锁文件和 runner 的指纹。RAG 服务只会在当前运行时策略、语料及所有指纹与报告完全一致时，在 `/public/workspace` 中展示该结果；代码或数据变动会让状态退回“待复评”。评测和指标断言由 `test_evaluation.py` 覆盖。
