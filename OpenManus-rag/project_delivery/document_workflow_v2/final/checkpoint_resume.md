# Checkpoint and resume contract

Each checkpoint is one versioned JSON recovery state (`document-workflow-checkpoint-v1`) containing workflow identity, template ID/hash/path, output path, configuration fingerprint, lifecycle and section states, section drafts, EvidenceCache snapshot and indexes, step/call counts, position, timestamps, and human-review flag. It contains full Evidence text only because resume needs it. The normal Trace and metadata-only Evidence JSON omit full Evidence text by default. Treat checkpoints as restricted recovery material; `.gitignore` excludes them.

CheckpointStore writes a temporary file in the target directory, flushes and fsyncs it, then atomically replaces the prior checkpoint. A failed replacement leaves the previous valid file in place. Resume rejects malformed JSON, incompatible version, changed template or incompatible config, section mismatch, invalid Evidence records/references, and unreadable completed drafts. It restores EvidenceCache and skips COMPLETE sections. Incomplete sections are retried with their cached Evidence identity retained.

The CLI uses `--resume WORKFLOW_ID --output OUTPUT` and may take `--template` for explicit path verification. The output path and template must match the checkpoint. A completed workflow cannot be finalized again. A new run refuses an existing `draft.docx`; a resumed PARTIAL run writes a uniquely named `draft-resume-*.docx` rather than silently replacing it. Recovery state and Trace files have separate retention/privacy concerns. This is local single-process checkpointing, not a distributed job platform.
