# Document workflow architecture

`DocumentWorkflow` fixes the business sequence: parse template, plan section tasks, collect field evidence, draft field values, mark missing fields, render a new DOCX, and emit Evidence and trace files. No free ReAct loop selects these high-level stages. The current prototype uses deterministic field queries and direct evidence text, with no online LLM invocation.

`TemplateParser` walks DOCX body blocks in order with `python-docx`. Heading 1–3 styles form sections and parent links. `{{field}}`, `【待填写】`, and simple table cells form fields; a leaf heading without a placeholder creates an implicit field. `SectionTaskPlanner` creates one task per fillable section. `TemplateRenderer` opens the original, replaces supported placeholders on a separate document instance, and saves only `draft.docx`.

`RAGTool` accepts a client with `query(question)`. `HTTPRAGClient` uses only `POST /query` on frozen RAG V2; `DemoRAGClient` performs offline lexical lookup over four simulated document snippets without persisting an index. The tool normalizes document/page/content into the existing `app.research.models.Evidence` model. `EvidenceCache` uses the existing `EvidenceStore` for stable IDs and deduplication, plus task and query indexes. Draft citation membership is checked against the current task's cache. This contract checks membership, not factual correctness.

Existing `BudgetLedger` enforces step, tool-call, duration, and zero-LLM-call boundaries. Existing `NoProgressDetector` observes cumulative evidence and covered-field counts. Existing `TaskPolicy` allows only RAG query, template read, and draft write in this workflow, and denies Browser/Search and write/publish capabilities. This is business policy, not a security sandbox. Existing structured `TraceContext` records query hashes, Evidence IDs, counts, and error types without full evidence text. `evidence.json` deliberately holds the text required for human review; it should be stored under the organization's approved access controls.

The old Knowledge Research Workflow, Browser/Search tools, candidate package path, and OpenManus/ReAct core remain in place and are not invoked by the new CLI.
